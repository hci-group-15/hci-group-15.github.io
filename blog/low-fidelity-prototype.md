## Lo-Fi Prototype B
We initially started using Figma, but quickly ran into some limitations with the design we wanted to go with, prompting us to switch to writing everything in Vue.js.

While that can take quite a bit more time, we felt like it would help us in the long run, next to the fact that one of the group members had used Vue.js quite a lot already.
That is, we can reuse some of the code from the lo-fi prototype in the high fidelity prototype, which is not (really) possible with Figma.

It also required some more proper coordination between the members to avoid merge conflicts for as long as possible,
which proved to be a bit of a learning curve for the two members of the group that had not really used `git` extensively up until this point.

In the end, we did likely spend a bit more time than others may have to achieve a similar result, but building on top of this,
had we elected to implement more features, would have been much quicker.

It also gave an introduction to Web Development to this part of the team, and gave us the flexibility to implement things that are not possible to do effectively in Figma.

For a next time, we should deffinitely commit to going with WebDev sooner to waste less effort in Figma first.
Figma is a great tool to work out the design and where to put things, but not how the interaction actually works, due to the "user friendly" nature of the tool,
which in general end up being more annoying than helpful when one is trying to get work done compared to "user focused" tools,
akin to the point of using an editor like NeoVim or Emacs being much more time efficient after putting in the time to learning them, compared to for example Visual Studio Code.

Creating lo-fi prototypes of course is a very important step that most solo-developers tend to gloss over or do haphazardly,
because it takes time that you could have otherwise spent on developing a real product.
While that strategy can work out for experienced solo-developers, it can lead to wasted effort later down the line.
